ScholarlyReview 项目全景

一个以 AI/ML 论文为主的学术自查与审稿助手。宿主模型（Claude Code 或 Codex）读论文、做判断；本地内核 sreview 管任务、预算、证据和准入。凡是写进报告的结论，都有原文引用，可以追溯。

Process

一次运行的流程

以 /paper-preflight paper.pdf（quick 档，启用隔离复核）为例。宿主不断 task claim → 完成任务 → task submit，直到内核返回 task: null。

01 · 内核

导入与冻结

PDF/MD/TXT 解析为带 block_id 的 DocumentMap，去掉行号和页眉，内容寻址去重。

02 · 内核

plan

合并配置，按档位生成任务，估算宿主耗时，列出权限、预算和控制等级。

03 · 宿主

understand

提取摘要、贡献、主张（原文引用）和待查假设，识别 AI 子领域。

04 · 宿主 → 内核

numeric

宿主只抄数字，内核用确定性程序复算，并考虑舍入区间。

05 · 宿主

checks

主张与证据、实验有效性、领域检查等。每条结论都要附证据引用。

06 · 宿主 → 内核

literature

只能用 sreview lit 查 arXiv/OpenAlex，不发送标题和原文句子。

07 · 隔离 Worker

verify

盲式反向复核：Worker 拿到中性问题和原文，看不到候选结论。

08 · 内核

export

快照、去重、准入、准备度判定，生成报告和修改计划。

每个任务的约束

  • 租约 30 分钟，带代次和 task_token，过期的结果只进审计
  • 最多 2 次尝试；被拒时返回具体错误，修改后重交
  • 先分析后复核；重交的任务可以使用复核时段
  • 文献检索遇到限流时会给出等待秒数，60 秒以内重试一次

Data model

数据与结论的生命周期

Claim 主张

论文的论断，必须带原文引用，锚定状态为 exact、fuzzy 或 unresolved。分 core 和 supporting 两级。

Evidence 证据

稿件引用、计算、文献、用户陈述。计算证据由内核生成，产物做哈希校验，被篡改的证据会被标为 corrupt。

Assessment 评估

某项检查对某条主张的判定：supported、insufficient_evidence 等。准备度看的是核心主张是否都被评估过。

Finding 发现

优点、问题或待澄清事项，有 potential_impact 和 impact，可以标为 duplicate_of 另一条发现。

Verification 复核

独立性分 fresh、inherited、same_context、human 四级，另记是否 blinded，结果可以确认或推翻发现。

ExperimentPlan

reproduction 档只生成复现计划，本版本不执行任何代码。

一条问题从提出到进入报告

宿主提交候选→ 内核校验 Schema、证据、锚定→ minor：直接 confirmed
major：生成 verify 任务→ 复核：validated / invalidated / inconclusive→ admit_finding 判定受众与类别→ 报告：优点 / 已确认问题 / 待确认问题

major 问题要被确认，必须满足以下之一：有确定性计算并重新核对过输入；由 fresh 隔离 Worker 复核；由 human 本人核对（verify-human）。同一会话自查（same_context）只能让它保持 unresolved。

Trust boundaries

谁负责什么

事项由谁决定说明
ID、状态、预算、租约内核模型提交的 key 由内核换成正式 ID；过期或被替代的提交只进审计
引文是否在原文中内核每条引用都与 DocumentMap 比对，标记 exact、fuzzy 或 unresolved
数字是否对得上内核宿主只抄写数字，内核计算；输入必须逐字出现在引用里
复核的独立性内核不采信自述；隔离与否由内核检查 Worker 的会话记录来判定
能否进入报告、给谁看内核admit_finding 和准备度判定；报告用确定性模板生成，不让模型润色
读论文、发现问题、写措辞宿主模型审稿质量取决于这一层，目前尚未评测
宿主自身的用量和工具无法约束交互模式下内核只能管住经它签发的任务，报告头如实列出
外发内容内核 + Skill检索词拦截标题和长句；Skill 禁止使用其他网络工具（属于协作约束）
Isolated verification

隔离复核 Worker

怎么隔离

  • 每个复核任务使用一个新的临时目录，里面只有说明、上下文（不含候选结论）、Schema 和稿件
  • claude -p --tools Read --strict-mcp-config --setting-sources local --no-session-persistence --json-schema …
  • 读取目录外的文件会被拒绝；自动记忆指向一个空目录；用完即删除副本

怎么判定

  • 检查 init 事件里的工具集、MCP 和 cwd
  • 检查每一次 Read 的路径，以及 permission_denials
  • 全部通过才记为 fresh + blinded，否则降为 inherited
  • 报告注明“同一模型家族的新上下文，不是统计独立的审稿人”

实测 4 次复核全部判定为隔离。每次 25–37 s、0.24–0.36 美元。Worker 确认了 BLEU 41.8/41.0 不一致，但把影响评为 minor；同一会话复核时评的是 major。

我们在这里

工具已经能独立跑通，过程可审计，major 问题也能由隔离进程确认。还不知道的是：它找到的问题和真实审稿人指出的问题有多少重合。

建议优先

小规模质量评测

选 5–10 篇有公开审稿意见的 OpenReview 论文，计算精确率和召回率，以此决定接下来是加强检查项还是收紧准入。约 100 美元，可以在后台批量跑。

之后

LaTeX 源码输入

表格单元格和公式能读准，数值复算的覆盖面会明显扩大。

之后

完整 managed 模式

分析任务也交给 Worker，费用按请求封顶，并适配 Codex。

Known limits

已知限制

  • 审稿质量没有经过评测，不能声称达标
  • 图片里的数值读不到；表格来自纯文本抽取
  • 不支持 LaTeX、DOCX、OCR；不执行代码
  • 交互模式无法计量宿主自身的用量和费用
  • 订阅登录用不了 --bare，Worker 仍会加载插件列表（但没有工具可以调用它们）
  • 工作区放在 OneDrive 等同步盘上时，SQLite 锁不保证可靠
